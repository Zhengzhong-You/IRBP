# Path generation and joint optimization settings

Edit `local_search.json`, or pass a smaller JSON object containing only overrides:

```sh
./build/irbp INPUT.json heuristic 5 RESULT.json --config OPTIONS.json
```

For a matched Path Generation comparison, replay one saved pool without integer repair:

```sh
./build/irbp INPUT.json pg 60 PG.json --pool-state C0.json --config OPTIONS.json
./build/irbp INPUT.json heuristic 60 REPAIR.json --pool-state PG.json --config OPTIONS.json
```

The `pg` result preserves the input incumbent and physical pool, merges returned logical paths into the complete input pool, and records LP objectives, stopping reason and final JRC ranking in `profile.path_generation_history`. The second command evaluates that fixed pool using the existing joint-repair replay. Set only `guidance_max_iterations=1` versus the bounded default to compare one batch and repeated LP/pricing with the same oracle.

- `max_new_blocks`: maximum unopened blocks in a bridge candidate assembled from current open segments. LP-guided and support searches can generate longer chains; this setting is not a feasibility constraint.
- `paths_per_group`: retained paths for each new-block count and minimum-load-support category. Zero retains all during debug. Single-new-block coverage candidates are retained additionally.
- `base_logical_paths`, `physical_paths_per_block`: baseline candidate limits in small repairs. Current and widest physical alternatives are also retained.
- `small_group_size`, `large_group_size`: numbers of demands reconsidered together.
- `expand_after_stalls`, `joint_after_stalls`: consecutive unsuccessful local repairs before group expansion and local tailoff.
- `overall_stall_rounds`: completed LP/pricing plus local-search rounds without improvement before joint repair. Newly generated paths are considered by local search before this counter advances.
- `open_logical_paths_per_demand`: total cheapest distinct elementary chains on currently open compatible blocks, including the cheapest chain if already retained. Zero disables this supplement. Bounded Yen/Dijkstra searches use current physical unit costs and handling costs, without a standalone minimum-load filter. Outputs enter the retained logical pool after base truncation and remain available to local, guidance and joint models; physical candidates are unchanged.
- `open_logical_search_seconds`: shared allowance for one all-demand supplementation pass before a guidance LP, clipped by remaining time. Demand traversal rotates across passes. Completed searches are reused for the same incumbent generation and fixed options; interrupted searches keep complete paths found so far and are retried later without being marked exhausted. Output distinguishes K reached, exhausted, interrupted and skipped work.
- `finite_stall_cycles`: zero preserves the original finite stopping rule. A positive value limits completed joint cycles without cost improvement, counting only after the post-joint local return. At the threshold, one final guidance/pricing and local return tests the pending joint-generated candidates before stopping; improvement resets patience. This is a heuristic effort limit, not an optimality certificate. Continuous mode ignores this limit.
- `benchmark_targeted_destroy`: false by default, selecting local groups through the existing related-demand rule. True enables the block-targeted comparator: virtually remove a block and its minimum-load closure to select demands for the local MIP. The incumbent remains its feasible start.
- `destroy_trial_max_seconds`: allowance for block-targeted selection when `benchmark_targeted_destroy` is true. Its minimum-load closure must fit the current local group limit; released demands take priority in that repair group.
- `joint_repair_max_seconds`: total time for one enrichment and joint-repair invocation. After it returns, the algorithm resumes destruction and local repair rather than calling another joint MIP directly.
- `schedule_trace_limit`: retained diagnostic events per trace. Full chronological events remain in the logs.
- `construction_relative_tolerance`: stop construction after a complete sweep when `(cost_before - cost_after) / max(1, abs(cost_before))` is at most this value (default `1e-6`). Zero continues until a sweep has no improvement. Only the overall time budget can interrupt a sweep; there are no separate construction pass, wall-time, or idle limits.
- `anchor_priority`, `origin_priority`, `endpoint_priority`: demand-group ranking weights.
- `joint_phase_max_seconds`: time for each destruction/local-repair stage before considering LP/pricing. Individual MIPs also obey `joint_mip_max_seconds`. Completed pricing rounds return to local search; joint repair waits for overall tailoff.
- `progress_log_seconds`: front-search progress-log interval; zero disables periodic messages. Phase boundaries, selected seeds, group members and MIP completions are logged separately. A previously optimal small-group model is skipped only while the incumbent and both candidate-path sets are identical; a time-limited solve is not marked exhausted.
- `continuous_search`: repeat group search and pool refinement after a candidate pool stops improving. Ordinary `heuristic 0` runs enable this automatically and keep running until interrupted; a finite deadline still applies. Subsequent cycles randomize demand seeds and equal-ranked partners, retaining the incumbent and route caches. `random_seed` makes this sequence reproducible. Identical exhausted integer pools and unchanged previously priced pools are skipped; this is a heuristic reuse rule, not a global optimality certificate. `continuous_idle_seconds` avoids busy polling when every proposed subproblem was already handled. Trace arrays retain the most recent events up to schedule_trace_limit; cumulative counters and full logs are retained. Explicit pool capture/replay remains a single diagnostic operation.
- `guidance_max_seconds`, `guidance_budget_fraction`: maximum logical-pricing time per scratch-RMP iteration (default `1e100`), clipped to this fraction of the remaining global budget. Elementary labeling keeps paths found before a time or memory interruption; interrupted searches are reported separately from a complete no-new-column pass. Every LP uses the remaining global budget.
- `guidance_iteration_seconds`: soft elapsed-time target per completed RMP iteration, default 10 seconds; zero disables this stop. The first iteration includes initial preparation and the initial LP; every iteration includes pricing, column/row additions and LP reoptimization. Check the target only after the augmented LP is optimal and row-complete, then stop before the next pricing search. The target never interrupts an LP.
- `guidance_max_iterations`, `guidance_plateau_window`, `guidance_plateau_relative_tolerance`: maximum pricing batches and LP plateau rule (defaults 10, 3, `1e-5`). Start with the initial optimal LP objective `z[0]`; each complete new-column batch is followed by an optimal LP with every used demand/block activation row present. Stop when the batch limit is reached or `abs(z[t] - z[t-window]) / max(1, abs(z[t-window]))` is at most the tolerance. This is an effort limit, not a full pricing certificate. A fresh terminal LP normally supplies return scores; time or LP failure falls back only to the last optimal, row-feasible solved prefix, excluding newly added unsolved columns. No integer model is solved inside Path Generation.
- `guidance_heuristic_pricing`: heuristic cost dominance for logical pricing, enabled by default. The same exact labeling kernel always retains the full visited-node set and rejects repeated nodes. False retains exact visited-set dominance and disables the neighborhood restriction.
- `guidance_neighbors`: at most this many distinct compatible successor yards per departure yard, default 32; zero keeps every compatible connection with a physical candidate. Rank heads by minimum retained physical-route length and keep all compatible parallel blocks with physical candidates to selected heads. Protect OD-direct blocks and every incumbent-path block. This mask affects only heuristic logical extensions; shared candidates, the physical graph and EUC search remain unchanged.
- `guidance_lp_method`: initial scratch-LP method: 0 for primal simplex, 1 for dual simplex, or 2 for barrier (default). Subsequent iterations and the terminal solve use dual simplex on the same incrementally extended model to reuse the LP basis. `guidance_crossover` enables automatic crossover for barrier; it is on by default because the no-crossover setting failed the existing-column dual-consistency gate on a regression case. `guidance_solver_log` records native barrier and crossover progress. `guidance_barrier_tolerance` controls barrier convergence; the existing JRC validity check is retained.
- `guidance_logical_paths_per_demand`: logical paths seeded per demand in the scratch RMP (default 4, including the incumbent path); remaining places use lowest estimated unit cost. Zero seeds the full pool. Pricing excludes only paths already in the scratch RMP, so omitted input paths may enter in later iterations. The complete input pool remains available to integer repairs and is preserved outside the return quota. Physical candidates stay fixed throughout Path Generation. This seed cap does not apply to the diagnostic LP used by integer-pool reduction. The scratch LP objective is conditional on its current physical and logical candidates.
- `support_search_seconds`, `support_paths_per_demand`: budget and candidate limit for paths that can help other demands meet block minimum loads. These are heuristic incentives; the joint MIP enforces actual costs and feasibility.
- `physical_alternative_seconds`, `physical_alternative_paths_per_block`: total budget per joint repair and new paths per opened block. Paths retain an existing prefix and find a different length-feasible continuation; all previous paths remain available.
- `record_candidate_pool`: diagnostic output of the last joint MIP's paths, iteration, and input incumbent. Disabled by default; enabling it adds output and timing overhead.
- `pool_mip_max_seconds`: initial solver time slice within a fixed joint model. A time-limited unchanged incumbent may trigger continuation of that same model, within the joint-repair and global limits. Pool-state replay retains its explicitly requested replay budget. This continuation does not start another enrichment or search cycle.
- `pool_fix_fraction`: at most this fraction of demands keep only their incumbent logical path (or remain unserved). Their continuous volumes remain free. Eligibility requires incumbent/LP agreement and positive alternative JRC; unserved demands are protected. Zero disables fixing.
- `joint_repair_max_demands`: absolute upper bound on jointly adjustable demand assignments, default 250; zero disables the cap. With at most 250 demands, this cap leaves every demand free. Larger instances rank groups using unserved loss, estimated EUC savings and each demand's share of current block opening costs. Minimum-load release closure keeps related assignments together; groups that do not fit are skipped, never truncated. Unserved demands without retained logical paths are excluded. Outside logical paths and served volumes are substituted before model construction. Shared blocks remain physically free and carry their full fixed-plus-free load; unaffected blocks and resource use are substituted as constants. No additional LP or path generation is required. This differs from the optional `pool_fix_fraction` rule, which fixes logical choices only. The LP guidance path cap and physical candidate pools are unchanged.
- `joint_arc_max_model_size`: maximum estimated variables plus rows for joint repair with implicit logical choices, default 100000; zero disables these choices. Before constructing the MIP, count variables exactly and bound rows conservatively, including newly active physical-path variables and all resource rows before removal of empty/duplicate rows. If the bound fits, each free demand with an unfixed logical choice receives an elementary compatible-block arc option, using only blocks with retained physical paths; at most one demand may choose its arc option in a joint solution. Otherwise the original retained-path model is built. Local repair, physical-path generation, demand selection and the 250-demand cap are unchanged. `JOINT_ARC_SIZE` and `pool_model_history[].arc_size_guard` record the decision and estimates.
- `pool_extra_paths`: additional lowest-JRC logical paths per free demand, beyond incumbent and LP-positive paths. Zero disables pruning. Minimum-load support can restore paths or release fixed demands; physical paths are unchanged.
- `pool_lp_weight_tolerance`, `pool_jrc_relative_tolerance`: LP-agreement and JRC thresholds for the optional reduction. The JRC threshold scales with the LP objective. These rules are heuristic, not safe variable-fixing certificates.
- `pool_capture_only`: stop before the first big MIP and save its incumbent and candidate pools. Replay that complete output with `--pool-state CAPTURE.json` to compare reductions from identical inputs. The replay budget includes pool loading, the extra reduction LP, selection, model construction and solving. Its bound is conditional on the retained pool. Every arm uses the captured incumbent as its MIP start and cutoff; the common front-stage time is separate.
- `guided_paths_per_demand`: total upper bound on new logical paths returned per demand, default 12. Converged calls retain only the lowest terminal-JRC paths up to this cap. Otherwise, first retain at most `guided_jrc_paths_per_demand` (default 8) lowest terminal-JRC paths from the solved RMP; then at most `guided_diverse_paths_per_demand` (default 2) remaining RMP paths by resource-Jaccard maximin. The EUC maximum is the remaining configured cap (default 2), using independent shortest paths on the complete compatible graph with physical candidates. Deduplicate against C0 and earlier selections. Unused category quotas are not reassigned or filled. All preexisting shared paths remain. RMP choices need neither positive LP volume nor negative terminal JRC.
- `seed_load_multiple`, `physical_length_weights`: physical seed-path diversification. A weight of `-1` means shortest length.
- `initial_physical_spp_paths`: examined cost-ranked elementary SPP paths when the cheapest physical path exceeds its length limit. The count includes the cheapest path; zero disables this supplement. Minimum-length and configured weighted SPP candidates remain available. Physical seeding and prefix deviations use SPP only, with full length/resource checks; logical JRC pricing uses labeling.
- `pricing_label_memory_mib`: label-memory allowance per pricing worker, default 16 MiB. The original exact `PricingWorkers` dispatcher uses up to `solver_threads` workers with local labeling/cost/mask/candidate caches. Fixed-dual searches are independent; their results merge deterministically by score, demand and path before the global 1,000-column batch cap. No per-column global lock is used.
- `solver_threads`, `final_mip_focus`: optimizer thread and joint-MIP focus settings. Logical pricing also uses `solver_threads` workers, capped by the number of demands. `final_mip_focus` defaults to 0 across joint-model formulations.
- `min_joint_seconds`, `min_pool_seconds`, and the `*_reserve` fields: minimum useful search time and return reserves.

The fallback defaults are declared in `local_search_options.hpp`. JSON overrides can be edited without recompilation; tests check validation, round-tripping, and omitted-field defaults. Results include the complete resolved `search_options`. Invalid values and misspelled keys fail explicitly. Domain checks, feasibility tolerances, and the original problem constraints are not relaxed by these settings.

Large-instance execution uses shared compatibility groups throughout native code. `proposal_block_threshold` selects a temporary demand-driven block domain above that input size; `proposal_hubs_per_demand` controls retained hub proposals and `shared_hubs_per_sweep` bounds common hub sweeps. This restricts heuristic search, not the input problem; original block IDs and domain size are recorded and returned plans are validated against the full input. The large-domain branch uses adjacency-based short chains, logical shortest paths and support pricing instead of enumerating all pairs of open-chain endpoints. `physical_tree_cache_size` bounds reusable shortest-path trees. `joint_mip_max_seconds` caps each small group solve within the remaining global budget.

For repeated large-instance runs, convert once with `code/scripts/pack_instance.py INPUT.json OUTPUT.zip`. The ZIP contains one portable `IRBPBIN1` binary member (`.irbp`); both zipped and uncompressed binary files are accepted alongside the existing JSON formats. The source JSON SHA256 and a sidecar manifest record provenance. Packing does not change block IDs, numeric data, compatibility, costs or capacities. Native validation and ZIP CRC verification still apply. Input parsing counts against the total budget; incomplete input returns `input_time_limit` with no claimed feasible plan.

Within each fixed candidate model, empty physical-capacity rows are omitted and identical left-hand sides are replaced by the tightest capacity. Pricing assigns that row's dual to a single original resource and zero to the other redundant rows. Equivalence classes are rebuilt after candidate changes; all original capacities remain in final plan validation. Incremental moves update only affected resources, including any existing numerical capacity residuals, rather than clearing and scanning the whole network.

Logical pricing retains at most 1,000 distinct negative-JRC paths per batch across all demands. Each admitted path receives its selection/volume pair and all required activation coefficients before LP reoptimization. RMP-based return choices use only the last solved row-feasible prefix. At termination, an actual LP plateau or a completed no-new-pricing pass counts as convergence of this restricted heuristic process. Converged calls return only the lowest terminal-JRC paths, up to the common return cap, without computing diversity resources or EUC paths. Time/iteration limits without convergence use the native JRC/diverse/EUC quota selector without a refill rule or external process. Classification uses the latest solved objective sequence even when plateau and a time/iteration limit occur together; a stop-string priority does not change the return mode. Only selected paths/sources and lightweight counts/times are recorded; the final shared candidate pool remains available to integer repair.

Construction selects its candidate block set once, with `proposal_hubs_per_demand=8` by default. There is no expanded-domain continuation. Singleton and direct groups are followed by one-hub bundles, selected two-hub pairs, and shared-block partner groups over all demand ODs. Group proposals rank savings relative to current served costs and remaining rejection penalties; complete feasible objective values still determine acceptance. The full physical graph is preserved.
