| Set | Nodes | Demands | Instances | Folder |
|---|---|---|---|---|
| N50, N100, N150 | 50, 100, 150 | 12 | 50 each | `small/` |
| N150K24, N150K48, N300K48, N600K48 | 150, 150, 300, 600 | 24, 48, 48, 48 | 10 each | `larger/` |

A file name gives the set and the random seed of the generator, for example `small/n100-s2026102348.json`. `manifest.csv` lists the size and SHA-256 of every file, and `sampling.csv` lists every seed that was drawn, in ascending order, with the reason a draw was not retained (an invalid draw or a network whose largest component is smaller than the target). No draw was discarded because of its computational results. The first ten N100 seeds were drawn in an earlier run whose rejected draws were not recorded; the two instances retained from that run are listed.

## Format

Each instance is one JSON object that all executables read directly. `irbp` also reads a ZIP file containing one instance and the packed binary written by `heuristic/scripts/pack_instance.py`.

| Field | Meaning |
|---|---|
| `nodes` | yards and other nodes: `yard`, classification `tracks`, `handling_capacity`, `handling_cost` |
| `arcs` | directed physical arcs: `from`, `to`, `link`, `length`, `cost`; the two directions of a link share its capacity |
| `link_capacities` | capacity of each physical link |
| `blocks` | candidate blocks: `from`, `to`, load bounds `lower` and `upper`, `length_limit`, `opening` and `interchange` costs, `slots`, `transport_factor` |
| `demands` | `from`, `to`, requested `quantity`, unserved `penalty`, and the compatible `blocks` |

The instances are generated by `generator/` as described in Section EC.3 of the paper. The generator estimates its distributions from data set L1 of the RAS competition, so regenerating them requires access to that data set; the generated instances themselves are provided here.
